**Anchor:** `github.com/istr/strike` at `7b09365` (2026-09-10). **Review date:** 2026-09-14 (revised the same day after the topology decision).

---

## 1. Verdict and decision

ADR-009's intent is right; its mechanism is not; item-0150 was missing three prerequisites, one of them a blocker. On top of that, the operator decided on 2026-09-14 to retire nested containerization from the tree entirely and to run the bootstrap in the sibling topology, with the decisive argument being that **nesting enlarges the trusted computing base**.

- **Right:** compare-before-publish, digest pinning of every external reference, reproducibility as an enforced gate, and the honest disclaimer that the proof is not a trusting-trust defense. With the Go toolchain a fixed, externally verifiable input, image equality tests the *orchestration* strike owns -- exactly the meaningful build-tool bootstrap of the companion reports.
- **Not realizable as written:** stage_3 "inside stage_2" (Finding F1).
- **Not expressible in the schema:** the compare step (Finding F2).
- **Retired by decision:** the single nesting of stage_1 (Section 4). strike is a client of exactly one engine the operator provides; it bundles, starts or runs inside no engine.

The recommendation is a three-check proof shape (Section 5), append-only amendments to ADR-009 and ADR-055, and a decomposition of item-0150 into four blockers and one follow-up, placed against the existing roadmap (Sections 6 and 7). The patch is emitted alongside this report.

## 3. Findings

**F1 -- Three documents, three topologies (fact).** ADR-009: stage_3 is produced by `bootstrap/lace.yaml` running *inside stage_2*. README: stage_2 runs lace "inside strike:stage_1". SECURITY.md: keep-id enables "nested rootless podman execution (e.g. for the stage_2 bootstrap step)". The lane's pack step bases the image on `cgr.dev/chainguard/static`; it has no engine. ADR-005 runs every step with `--cap-drop=ALL`, read-only rootfs, no-new-privileges and `--network=none` unless peers are declared, non-configurable (confirmed in `internal/container/engine.go`). **Inference:** stage_3-inside-stage_2 requires either a step reaching the stage_1 engine or a doubly nested engine; both are excluded.

**F2 -- The compare is not expressible (fact).** `#InputRef.from` requires `{step, output}`; an image output has no output name and is addressed by step (ADR-046); a pack step yields exactly one image output. `strike compare` compares two files. **Inference:** the compare must be a control-plane step kind that consumes two producing steps and emits a file output the deploy names (ADR-039 D5).

**F3 -- Source ingress and anchors (fact).** `lane.yaml` references a step `src` it does not declare; every anchor is the fixture certificate; every endpoint is `*.example`. ADR-011 prescribes a containerized fetch step; `contract/provenance` has the git record. Whether a fetched tree's output digest is stable across fetches depends on the output wrap canonicalizing checkout mtimes -- to be measured.

**F4 -- Toolchain lock (fact + inference).** Neither build sets `GOTOOLCHAIN=local`; under the default a newer `go.mod` line triggers a download through the declared proxy peer; the record would carry the peer but not the toolchain that compiled the binary.

**F5 -- stage_0 and lane builds differ (fact).** Containerfile: `-trimpath -ldflags="-s -w"` on a git checkout (VCS stamping on). Lane: adds `-buildvcs=false`. Different toolchain builds as well.

**F6 -- The sibling run line is measured in its mechanics, not with the stage_1 image (fact).** ADR-055 D7 M2/M3 measured socket bind-mount, host networking and the mapped user for the dev container. The bootstrap reuses the same mechanism with a different image and no shell; the nested variant that item-0150 originally required was never measured and is now retired.

**F7 -- TCB understated (fact).** See the reconciliation table. The Containerfile installs git via `apk` without a pin (item-0062 finding; item-0151 ratification point).

**F8 -- Documentation drift (fact).** Containerfile header documents `COSIGN_PRIVATE_KEY`/`COSIGN_PASSWORD`, retired by ADR-043; the README bootstrap narrative describes a lane that does not exist; the README lane excerpt is schema-invalid (item-0064 adjacent finding; item-0154 scope).

**F9 -- Build step is not hermetic (fact, non-blocking).** The build step reaches `proxy.golang.org` and `sum.golang.org`; reproducibility holds through `go.sum`; the SLSA Isolated clause holds because the peers are declared and recorded. Vendoring or a module-cache step would remove the network; post-beta.

**F10 -- `strike compare` is the last production host-write site (fact).** item-0122 records it behind the forbidigo exemption. A control-plane compare step makes the subcommand redundant (item-0125's surface).

**F11 -- No trust-bearing engine image exists (fact, verified 2026-09-14).** The uploaded report concludes there is no Chainguard podman image and recommends `ubi9/podman`, `mgoltzsche/podman`, or a self-built image. Checked against primary sources: the public build-config repository `chainguard-images/images` -- per its README the source of truth for published images -- lists 54 image directories; `podman`, `buildah`, `buildkit`, `skopeo` and `prometheus-podman-exporter` are not among them (present are, among others, `go`, `static`, `git`, `crane`, `ko`, `cosign`, `wolfi-base`, `docker-dind`). The uploaded report's claim that buildah/buildkit/skopeo exist in the free Starter tier is therefore not confirmed; at best they are paid-tier images, which could not be measured without registry access. `wolfi-dev/os` on `main` carries `crun`, `conmon`, `netavark`, `slirp4netns`, `fuse-overlayfs`, `shadow` and `containers-common`, but no `podman`, `buildah`, `skopeo`, `passt`, `aardvark-dns` or `catatonit` definition (the repository is a read-only public clone, so absence may mean internal-only). Absence of `passt` matters: ADR-031 makes pasta strike's only network dependency, so a self-built engine image would have to build podman and passt from source. buildah itself "follows a simple fork-exec model and does not run as a daemon" (upstream README): it offers no API for strike to drive under ADR-001, and as an in-process library it would be the "weak isolation" variant ARCHITECTURE.md rejects. buildah does support reproducible Containerfile builds (`--source-date-epoch`, `--rewrite-timestamp`, `--timestamp`), and `podman build` is buildah as a library -- the one place buildah already is in the bootstrap (stage_0) and stays. The free-tier `chainguard/go` image is `latest`-only and currently carries go 1.27.1; the Go version behind the lane's pinned digest is a measurement.

## 4. Sibling versus nesting -- the weighing and the decision

Terms: **N2**, an engine inside a step container, is excluded by ADR-005. **N1**, an operator-started container that carries its own engine and hosts strike (stage_1 today, the "nested topology" of ADR-055 D5). **N0**, strike in a container with the operator's engine socket bound, its steps siblings (the dev container, the forge runner, the harness). Rootless podman-in-podman is a documented, supported Podman mode, so "anti-pattern" applies in full only to rootful, privileged docker-in-docker; what remains against rootless N1 is fragility, state duplication and TCB growth.

| Dimension | N1 nesting | N0 sibling |
| --- | --- | --- |
| Boundary step -> control plane (the SLSA L3 boundary) | A step escape lands as the same uid inside the stage_1 container -- at strike, the token, the inner socket. No extra boundary for the control plane. | A step escape lands in the user's engine context -- at the strike container, the token, the host socket. Same boundary, same mechanisms. Tie. |
| Boundary step -> host | Two user-namespace boundaries. Pro N1, for the host only. | One boundary; identical to the daily path. |
| Privilege of the control plane | Only the inner engine and its tmpfs. Pro N1 (least privilege). | The host socket: control over all of the user's containers, host mounts possible. User-level (rootless) and exactly the power the dev container has daily. |
| Confinement of the operator container | Needs `unmask=/proc/*`, writable storage, nested user namespaces; host hardening (e.g. AppArmor user-namespace restrictions) hits exactly that first. Unmeasured. | A normal rootless container plus socket, host networking, keep-id. Measured (M2/M3). Pro N0. |
| Trusted computing base of the proof | Host engine **plus** inner engine (unattested community image) plus its runtime stack. The host engine does not drop out: it starts and can inspect the container. Strictly larger. | Host engine (distribution-built, version in the record), images, toolchain. Pro N0 -- **decisive**. |
| Engine configuration as a build input | Pinned by the image (`containers.conf`, `storage.conf`, `registries.conf`). Pro N1, substantively: a host `containers.conf` can inject environment into every container, an undeclared influence. | Operator infrastructure, not recorded. Compensation: engine identity in the E layer, cross-host reproduction (C2), optionally a post-create check that the container environment equals what strike declared (item-0156 measures feasibility). |
| Ephemeral state | tmpfs, everything vanishes with the container; no residue on crash; no prior cache. Pro N1, real. | Storage persists; residue on crash (item-0136 mitigates); item-0124's cache gap applies. Compensation: cache-bypassed double build (C1 is exactly the SLSA cache clause), fresh engine storage, or the ADR-055 D8 local guest -- a VM boundary is stronger than any container nesting. |
| Resources | RAM-backed tmpfs must hold every image and the build; OOM risk on a D8 guest; double pulls per run. Pro N0. | Shared image store. |
| Network | Mediator in its own netns: locally unreachable, no port collisions. Pro N1, small. | Mediator on host loopback (`--network=host`, M2): locally reachable, collisions possible -- identical to the daily path. |
| Fidelity of the proof | Runs in a topology used nowhere else (ADR-055 rejected it for daily use); N1-specific failures are false alarms of the proof. | Runs in the production topology; what is proven applies to what ships. Pro N0. |
| Self-containment | "One image contains the whole proof" -- but `podman build` is not bit-reproducible, so stage_1 differs per operator; only the binary inside is comparable. | One image plus the engine the operator has anyway. |
| Host engine version | Decouples strike from the host engine; the one case with weight (a hosted forge runner may ship an engine below the 5.0 gate). | The requirement is uniform: Podman >= 5, rootless, pasta -- consistent with "the engine is the one host capability" (ADR-055 D1). |
| Provenance semantics | Two modes -> two builder ids (SLSA v1.2), two engine-identity semantics. | One mode, one id; item-0005's declared engine identity applies uniformly. Pro N0. |
| Code, docs, measurement | Own Containerfile stage, community base, special run line, a spike for a topology used once, a builder-id item. | Containerfile shrinks to builder + static; the spike becomes a re-measurement of M2/M3. Pro N0. |

**Decision (operator, 2026-09-14):** N0 only. Nesting's honest advantages -- least privilege for the control plane, ephemeral state, pinned engine configuration, host-engine-version independence -- are not trust; its cost is a larger TCB while the boundary SLSA L3 requires is the same. The resulting principle extends ADR-001 and ADR-055 D1/D2 to a closed figure: *strike is a client of exactly one engine the operator provides; it bundles, starts or runs inside no engine.* Scope: strike's execution path. A harness service that happens to be a container runtime (the k3s deploy target of item-0141) is a target, not an executor, and stays permitted; a remote engine over mTLS is a client-of-one-engine case and stays consistent. Optional structural enforcement: a lintdoc rule that no Containerfile in the tree installs an engine.

## 5. Recommended proof shape (recommendation)

| Check | What runs | What it proves | What it does not prove |
| --- | --- | --- | --- |
| **C1 -- in-lane double build** | As a sibling on the operator's engine, the lane fetches the pinned commit, builds and packs the image, then builds and packs again with `forceRun: true`; a control-plane compare step asserts identity before the registry deploy. | Orchestration determinism within one control plane and one engine, including the SLSA cache clause. Catches timestamps, unsorted iteration, `time.Now()`, non-canonical layers. | Anything the engine or host contributes identically to both builds; that the built strike can orchestrate. |
| **C2 -- cross-control-plane, cross-host** | The commit gate (item-0063) runs the *released* strike as a sibling on the forge runner's engine; on a release commit its plain `go build` step is packed with the bootstrap lane's pack spec; the digest must equal the one the bootstrap published for the same commit from the operator's endpoint. Enforced by the release procedure from the second release on. | Independence from the control-plane binary (genesis-built vs released), from the engine instance and from the host. This is the Gradleception-equivalent self-hosting proof; with one topology its diversity comes from the two hosts. | Independence from the toolchain image; anything shared by both hosts' engines. |
| **C3 -- strike-free rebuild** | A documented `podman run` of the pinned Go image executing the lane's `go build` against the tagged commit; the binary's sha256 must equal the binary inside the released image. Needs a rootless engine and nothing else (ADR-055 D1). | That a distrusting operator can verify the release without executing strike. | Compiler trust. |
| **Informational -- toolchain diversity** | After item-0062 aligns flags and versions: stage_1 binary (go.dev toolchain) vs lane-built binary (Wolfi-built toolchain). | Agreement between two independently built compilers of the same version. | A backdoor in shared source. Lost if the builder stage moves onto the lane's toolchain image. |

Companion decisions: the stage_1 image carries no engine and its command names its lane file explicitly (fork 1 of item-0150); the compare is chain-independent, so the workstation proof deploys under the local harness and the publish runs under the public chain where an id token exists (fork 2); `GOTOOLCHAIN=local` and aligned flags in both builds; the amendments enumerate the TCB honestly and state that the proof is not a trusting-trust defense and that reproducibility is beyond, not part of, SLSA L3. The published run line takes the shape the dev container already uses -- engine socket bound, `CONTAINER_HOST` set, host networking, keep-id -- and its exact form is item-0156's measurement, not this report's.

## 8. Open decisions for the operator

1. **One lane file or two** for the workstation proof (harness chain, local registry) and the publish (public chain). Static inline anchors make one parameterized file impossible; two files or one file with two deploys are the options.
2. **The toolchain-diversity trade in the Containerfile:** apply the cgr.dev rule to the builder stage and lose the informational stage_1-vs-lane comparison, or keep a second toolchain provider in stage_0 on purpose and record the deviation (item-0062).
3. **Structural enforcement of the no-nesting principle** (a lintdoc rule against engine installs in Containerfiles): now, later, or never.
4. **Hermetic build step** (vendored modules or a module-cache step) -- post-beta or beta.
