Surfaced by the item-0049 landing run, which rewrote every lane fixture's
resolver block and could not see these five: they carry a .parked extension, so
the *.yaml discovery grep skipped them and no test parses them.

They are not merely stale in the resolver field. valid_deploy.yaml.parked also
carries a top-level registry: key that #Lane does not declare, and its own
header says it is invalid under ADR-051 D6 and D9. So a fixture that has drifted
through at least one ADR cycle while parked is not saved work; whoever revives
it rewrites it anyway. Patching only the resolver block would leave them
unparseable while making them look maintained, which is why item-0049
deliberately left them alone.

Leaning toward deletion under "removal is the default resolution", but the
parked notes claim reactivation is intended, so the call is the operator's and
is made per file, not in bulk.

Amended 2026-10-25. Item-0164 deleted
cmd/strike/testdata/image_from_lane.yaml.parked by operator decision of that
date: its producer was a container step declaring the image output, a shape
item-0164 removes from the lane schema, so the fixture encoded a use case
that no longer exists. The use case it sketched, a step that builds a base
image for a later step, is a directory output packed onto a digest-pinned
base and run through imageFromStep. Four fixtures remain.
