The CUE-side analogue of item-0093 (gotypelint). item-0093 folds the two
Go-type linters into golangci-lint analyzers; cuelint is the third Makefile
linter and stays outside that merge because it is a CUE-coverage gate, not a
Go-type gate. It is today a standalone on-demand tool, intentionally not in the
aggregate lint target. Keeping it go-native (analyzer plus standalone survey)
is what lets its Makefile wrapper fall away when the file is retired
(item-0096). Sequence after item-0093 so the shared analyzer/plugin idiom is
settled once, not invented twice.

Naming is in scope: the tool is renamed to lintcue with the Makefile target
lint-cue, so it matches the prefix shape its siblings use instead of standing
alone as the one suffixed name.

Amended 2026-09-05 at aaaf280: the analyzer and plugin framing above is
retired. item-0093 did not fold the Go-type linters into golangci-lint
analyzers. It measured that the default issue-processor drops every diagnostic
whose file is not a .go file, and made the tools plain commands declared as
tool directives and invoked as go tool, the shape ADR-050 set for the CUE CLI.
That verdict binds harder here: the contract-syntax half of this gate positions
its findings on .cue files, and the coverage half builds a cross-package use
map over the whole load, which a per-package analysis driver cannot supply
without an exported-fact scheme. There is also no standalone survey entrypoint
to preserve; this tool has only ever had one code path, and the clause was
carried over from item-0093.

The coverage half gains the tools-tree self-exclusion item-0093 gave linttype.
This is a deliberate behavior change with an effect, not a no-op: since the
sibling linter moved into the root module its exported json-tagged survey
record, which also carries one unexported field, has been reported both as a
mixed-field struct and as a hand-written type that ought to be generated. A
survey record of a measuring instrument is not a contract type, so both
findings fall with the exclusion and no follow-up item owns them.
