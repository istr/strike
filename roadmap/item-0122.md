ADR-035 removed the host scratch from the output side and named what it left behind: the registry helpers still round-trip through a host temp directory when building and loading layers. ADR-036 closed the input side. This item closes the named remainder, which is wider than the one sentence suggests. Six production sites write payload to the host disk: singleImageTar in internal/registry/client.go writes a full OCI layout with every layer blob through layout.Write before taring it into a buffer, on every image load; ExtractMainImage in internal/registry/imagewrap.go unpacks a layout tar into a temp directory on every load and on every registry deploy push; LayerDiffIDs in internal/registry/imageextract.go does the same on every cache hit; the pack input extraction in the same file materializes producer content into a destination directory; writeOCILayout in internal/executor/pack.go assembles the pack layout in a temp directory; and executePack in cmd/strike/run.go holds the resulting layout tar in a host temp directory for the duration of the step. singleImageTar is the sharpest case: its doc comment claims an in-memory buffer while the layout, blobs included, goes to disk first. ADR-035 states the rule as in-memory canonicalization keeping payload off the host disk, and requires any spill to be explicit and isolated rather than the silent default; this is the silent default. The sealed registry deploy carries the whole artifact across the host disk twice, once for the pack layout and once for the export read, which makes this a supply-chain surface on the sealing path and not only an internal tidiness question.
