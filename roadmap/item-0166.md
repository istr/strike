## Amendment 2026-10-29 at 84b5753: the credential is a workload-identity token, the targets are zot and quay.io, the item runs after item-0167

Operator decisions of 2026-10-29, after a grounding of the tree and a
primary-source survey of zot, Gitea, GHCR and quay.io. The mechanism is
the one ADR-025 deferred as "OIDC workload identity for non-SSH client
authentication (HTTPS peers, OCI registries)" and that ADR-037 D5.1,
ADR-038 D3 and ADR-054 D5 left open: a new record, ADR-058, settles it
before this item is authored, fork by fork as ADR-057 was. The decisions
already taken: the credential is an OIDC identity token minted with the
registry's own audience, never a static password or a personal access
token ("PAT is dead, at least for strike"); where the registry validates
the token itself the token is the bearer (zot `bearer.oidc`), where the
registry federates robots the token is exchanged on the registry's own
host for a one-hour robot token and the robot name is declared in clear
(quay.io, `/oauth2/federation/robot/token`); the declaration carries the
secret reference apart from the target's trust anchor as before.

Gitea and GHCR are struck as candidates: neither offers a workload-identity
exchange for its registry (Gitea's job token cannot push packages, GHCR
has nothing outside its own workflows), and neither serves the OCI 1.1
referrers API that strike's verification discovers bundles through.
quay.io is the public candidate: private repositories are a paid plan,
accepted; the risk that a tagless manifest is garbage-collected after its
temporary push tag expires is open and is the first measurement of the
spike, on a free public repository, before any paid plan starts. The
harness stands in for the registry identity as it does for the builder
identity (ADR-057 D12): zot is switched to `bearer.oidc`, and the harness
Keycloak issues the registry-audience token, both in scope of this item.
Whether one token carries two audiences or two tokens are minted, the
realm-on-another-host case, the ambient keychain on the write path and
the read side of strike verify against a private repository are ADR-058
forks, not decided here.

Order, ratified 2026-10-29: item-0085, item-0081, item-0167, then this
item. item-0167 turns the token read at the deploy into a source that
mints per audience, which this item uses for the registry audience
instead of building a parallel channel; item-0081 puts the identity token
on the redacting secret type, which the second token inherits; item-0167's
harness spike configures the same Keycloak this item extends. Both are
therefore dependencies of this item, not ordering preferences.
