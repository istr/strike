The produce path computes each output layer's diff_id control-plane-side, before the assembled image is ever loaded into the engine, so a consumer that recomputes sha256 over the uncompressed layer and compares it against the handle terminates at a value strike itself produced. The cache-hit path does not: registerCachedOutputs exports the cached image and takes the handle's diff_id from the config the engine returned. A later consumer check against that handle therefore binds two exports of the same image to each other, not to bytes the control plane produced, and an engine that answers consistently defeats it. The same gap exists for image outputs and is closed there by refusing to cache a step whose image a deploy seals (sealsArtifact); file outputs have no equivalent, and a cached file output can be delivered into a pack step whose own image is sealed. Whether that indirection is acceptable is a trust-boundary question about what a verifier may conclude from the attestation, not a code defect, which is why the resolution may be an ADR rather than a change.
