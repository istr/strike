The remediation half of the BC-02 limit ruled in item-0072: the log/error formatting exclusion is scoped to the formatting expression, so safeName -- derived once from a primitive.Identifier and then threaded as a plain string parameter beside that identifier through executeDeploy, resolveImageDigest, checkCache, executePack and executeContainerStep -- is program state and D1. Sanitisation belongs in the logging seam; slog is the stdlib mechanism that puts it there.

Amended 2026-08-19 after a code check: sanitizeForLog is implemented twice, not
once. cmd/strike/helpers.go and internal/container/transport.go each carry a
private copy, byte-identical down to the strings.Builder Grow, the r < 0x20 ||
r == 0x7f predicate and the '_' replacement, in two different packages with no
shared owner. There is no logging package today -- both call sites reach for the
stdlib log directly -- which is why the helper was copied rather than imported,
and it is the root cause the slog seam removes.

The two copies are not the same kind of debt and the retirement differs. The cmd
copy is the threaded-safeName case this item was written for and mostly falls
away with the threading. The internal/container copy guards a real log site: it
sanitises the engine AUDIT line, whose req.URL.Path folds in lane-derived
container and image names, so it cannot simply be deleted -- it has to move into
the seam or the audit trail loses its forgery guard. Retiring one copy and
leaving the other satisfies the old wording while leaving the duplication
standing, which is why the acceptance now names both sites.
