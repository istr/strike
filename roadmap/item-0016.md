Deferred follow-on from ADR-046 D9: machine-enforce the layer direction rather than rely on the file boundary plus review. The original base-/api-/wire- filename-prefix basis is dead -- the spec-layering reorg produced per-package tiers (primitive, concept, foundation/transport), not prefixed files within one package -- so the lint keys on the current package and tier layout instead. The Go side already enforces its layering via go-arch-lint; this is the mandatory CUE-side counterpart in the build gate. Whether the rule is a custom lint (tools/lintfrom mold) or an off-the-shelf CUE linter, and the exact classification predicate, are settled at authoring against the landed tier structure. Still assumes the internal API is wired end to end (item-0001).

Absorbed from the item-0011 completion report: the second axis. Declaring a
CUE field without the optional marker does not make it required in the
exported JSON Schema when its type is a list. CUE gives a list type an
implicit empty-list default, and the exporter drops a defaulted field from
the required set, so no array property anywhere in contract/lane.schema.json
is required. Seven definitions are affected -- Capture (command, mounts,
peers), CaptureSet (captures), ImageConfig (cmd, entrypoint), PackSpec
(files), SSH (knownHosts), Step (args, inputs, outputs, peers, secrets), and
TrustedRootReplica (certificateAuthorities, ctlogs, timestampAuthorities,
tlogs) -- and several of those fields are written without the optional
marker, so the contract reads as requiring what the gate does not check. The
effect is that strike validate accepts a lane omitting the field and the
omission surfaces later, at runtime, if at all: an inline trust root with no
ctlogs block validates clean and is rejected only when ParseTrustedRoot runs
at verify time. Some of these lists are genuinely optional and their
declarations should gain the optional marker instead; the item owns drawing
that line once and enforcing whichever side each field lands on. This shares
the lint step and the build-gate wiring with the layer-direction rule, which
is why it lands here rather than as its own item.

## Amendment 2026-11-14 at 0b35cd9: the decisions, and the two parts

The operator closed every open fork on 2026-11-14. The work lands in two
instructions: part 1 changes no schema, part 2 carries the
schema-and-codegen chain. The item's profile becomes large/deep, which
part 2 needs; part 1 runs at middle/brief.

Host and wiring. lintcue splits by input, as an interim. go tool lintcue
-contract runs the CUE-source checks over contract/ and gates as a recipe
line of the aggregate lint target; go tool lintcue with a package pattern
runs only the Go coverage check and stays on demand as lint-cue. No make
target is added, because make is removed later. item-0050 folds the two
modes back into one gating run once the Go side is green.

The direction rule. The tier model is already decided by ADR-044 and
ADR-048 (5); this item declares no model of its own, only each contract
package's tier: primitive; concept (endpoint, output, provenance,
record); wire (lane, attest, trustlayers); vector (crossval). A contract
package imports only from a strictly lower tier. A package directory or
an import with no declared tier is a finding. The ADR-048 amendment
this item writes names the four tiers and records why crossval sits
above the wire.

Fail closed. The contract mode aborts when a contract package fails to
load; a load that fails is never skipped in silence.

primitive-reuse. A primitive whose value is a bare identifier -- string,
or another definition -- owns no grammar, and the rule no longer matches
it. Matched by that identifier, it claimed every field of that type, and
the last such primitive read won the name in the report. The fix lands
in part 1.

Required-ness, part 2. A list field is either optional (?) or non-empty
([T, ...T], the form steps already uses), and a required map field made
only of patterns becomes optional; there is no required marker (!).
Optional: Step.args, Step.inputs, Step.secrets, PackSpec.files,
CaptureSet.captures, Lane.secrets, Step.env, StepResult.outputs.
Non-empty: Capture.command, SSH.knownHosts, the four TrustedRootReplica
lists and certChain.certificates. crossval conforms in the same change,
its maps step.env, input_hashes, source_hashes and the AssembleImage
files map included. contract/attest is deferred as a whole, owned by
item-0004: part 2 amends item-0004 with every affected attest field --
subject in the three statements, provenance in Informational and in the
informational predicate, ObservedPeer.resolved, and the maps artifacts
and the two peers. The rule gates in the contract mode, and its attest
deferral names item-0004 as owner wherever the gate sees it.

The knownHosts narrowing reaches the frozen attestation wire through
endpoint.#Endpoint; part 2 records it as a dated freeze event in the
Beta Definition of Done, as 24d4fee did. The freeze baseline covers only
the tree of contract/attest, not the packages it imports; item-0193 owns
that gap.

Runtime guards the schema makes dead go with their tests: the capture
image and command guards in internal/deploy and the empty host-key
guard in internal/capsule. The trust-root checks in internal/verify
stay, because they also parse roots that never passed the lane schema.

Part 1 also lands the SPEC-PACKAGE-LAYERING corrections recorded above,
the crossval line with them (crossval imports primitive as well), and
the .go-arch-lint.yml comment.

## Amendment 2026-11-14 at 433e6a2: the decisions of part 2

Part 1 landed at 433e6a2. The operator settled the open points of part
2 on 2026-11-14.

The required-ness rule is rule (6) of ADR-049, which part 2 writes:
inside a definition, a list field is optional or non-empty, and a map
field made only of pattern constraints is optional. It reaches every
field inside a definition, nested ones included, and nothing outside
one: the three data fields of trustlayers (layerOf, sections, fields)
declare their pattern and their entries in two declarations and stay
as they are. The value of a pattern constraint is the type of each
entry, not a field, and is not reached either.

The five crossval lists (spec.files, diff_ids, step.args, captures,
peers) become optional, with the four crossval maps. Each has a
defined empty case, and the vectors keep writing the empty lists.

The attest deferral is field by field: nine entries in the lint, each
naming item-0004 as owner. An entry that matches no field is itself a
finding, so the list only shrinks.

The invalid lanes are derived in one table test: for each of the seven
non-empty fields it removes the field from a valid fixture, and empties
it, and requires schema validation to reject the lane and name the
field.

Found at the anchor: internal/lane/testdata/invalid_trustroot_both.yaml
has no ctlogs. With ctlogs non-empty that fixture would fail schema
validation before it reaches the mutual exclusion it is named for, so
part 2 gives it the ctlogs block of valid_trustroot_inline.yaml.

## Amendment 2026-11-14 at 708323a: part 3, the fields of a pattern's entries

Part 2 landed at 708323a. Its executor found that required-collection
reaches a field inside the struct value of a pattern constraint, as it
should, but names the pattern's path segment empty, as it does every
label that is not an identifier: a probe reported #ZZProbe.m..x, so a
deferral would have to spell an empty segment. It also found that the
sentence of rule (6) "the value of a pattern constraint is not reached"
reads as if it exempted such fields.

The operator decided on 2026-11-14: such fields stay reached, since
each is a field of every entry; a site path spells a label that is not
an identifier by its normalized source (#ZZProbe.m.[string].x); a dated
amendment to ADR-049 and the type survey rulebook say so. The
correction lands as part 3 of this item, before it retires.
