## Amendment 2026-10-25 at 11e874d: restated as the validating bootstrap lane

Operator decisions of 2026-10-25. The ADR-009 amendment of 2026-09-14
governs; where this item contradicted it, the item was wrong. The item now
replaces the root lane.yaml, which never validated, by a lane that does:
the source step, a generate step, the build and pack steps, and one
registry deploy leaf, because every leaf is a deploy (ADR-039 D5). The
second build is item-0150's and the compare is item-0158's.

The git provenance record ADR-009 names is the source step's own record in
the sense of ADR-011: the lane digest the sealed attestation carries covers
the commit the step declares, and the observed peers record what it
reached. The step declares no provenance block, and no second step writes a
record; nothing in the tree could produce one from a shell-free git
invocation. Read at 11e874d: the step image of a container step holds only
its output layers, with ownership and mtime zeroed, entries sorted and a
fixed created stamp, so repeatability rests on the bytes of the output tree
alone; the repository metadata is kept outside it, except for the
one-line pointer file a separate git directory leaves, which is the same on
every fetch.

The fetched tree carries no generated sources (the generated Go types and
the contract JSON are not tracked), so a generate step precedes the build.

The bar is validation and correct pins. The git image is
cgr.dev/chainguard/git, the image the operator identified as d54cdf4f9408,
pinned by the full registry digest the executor resolves for it. The deploy
target, the keyless chain, the oidc block and every TLS anchor are
placeholders that validate; making them real and running the lane is
item-0150's. The commit pin in lane.yaml and README.md is HEAD~1 of the
commit carrying it, an interim rule until item-0062 sets the release
behavior.
