Created by the roadmap revision behind ADR-055; the ADR names this item
in D3 and in its consequences.

The version at c2f602c is a measured first version: its Node.js runtime
comes from a distribution repository, is past upstream end of life since
2026-04-30 and below the agent package's declared floor, and the agent
arrives through a Dev Containers feature whose version floats on
rebuild. A feature is a shell installer over unpinned repositories, which
is why D3 forbids the mechanism rather than pinning it. The Containerfile
header says so; this item removes that header.

The pin gate rides here because the change it guards lands here, so the
gate is green at introduction (the item-0145 principle). It lives in
lintdoc, the existing home for tree-wide checks that need no Go type
information; no new tool. Ratification point: the package-manager rule.
At the anchor both this Containerfile (apt-get for nodejs and npm) and
bootstrap/Containerfile (apk for git) install from a distribution
repository; a rule that forbids it is red on both until each finds a
pinned source -- for git, a cgr.dev image that carries it is the obvious
candidate to measure.

## Amendment 2026-11-01 at e654c5a: the feature and Node.js are gone

The dev container part landed except for the base image. devcontainer.json
declares no feature, and the feature lockfile is removed; the extension the
feature contributed is declared under customizations. The agent is the native
binary of the version-pinned @anthropic-ai/claude-code-linux-x64 package,
fetched under an ADD checksum and copied out of a tools stage. It needs no
JavaScript runtime, so the image carries none, and the build consults no
distribution package repository. The Go tools are built in the same stage.

Open in this item: the cgr.dev base-image measurement, the removal of the
narrowed Containerfile header once that measurement is settled, and the
lintdoc pin gate. The ratification point narrows with this: the dev container
no longer installs from a package manager, so a package-manager rule is red
only on bootstrap/Containerfile, whose builder stage still installs git with
apk.

## Amendment 2026-11-08 at 71da092: one base mechanism, no C toolchain, the container check

Operator decisions of 2026-11-08; the goal, the acceptance intent and the
links above are restated to match.

Scope. The cgr.dev rule for the bootstrap builder stage moves here from
item-0062, which was written before the dev container existed: the dev
container and the builder stage take Go, and git where it is still needed,
through one mechanism, measured once and applied to both. The builder stage
uses the lane's Go toolchain; item-0160 takes the toolchain diversity this
ends into the bootstrap lane's reproducedBy gate.

Final stage. The running dev container carries only the tools the work
needs. It has no C toolchain, so cgo fails instead of succeeding quietly;
make leaves with the Makefile (item-0096). The race detector needs cgo and,
on Linux, a C compiler, so how the working-tree gate keeps -race is
measured -- the pure-Go detectors around the open upstream proposal
golang/go#76786 among the candidates -- and ratified before the rework is
authored.

Shell expansion. The builder expands a build argument in ADD, not in RUN, so
a git source in ADD may replace the builder's git init, the shell-form fetch
and the checkout, and git in the builder with them. Whether it does is
measured: the .git/HEAD the render stage reads, whether the fetch needs git
on the host, whether the commit is verified, and the --checksum form a git
source takes.

Gate. The container check in lintdoc lands first and green. Package-manager
installs are decided as an allowlist: every RUN is the exec form and starts
a program the allowlist of its Containerfile names, so a repository-resolving
installer has no place, and a shell-form RUN is refused because the gate
cannot see what a shell starts. The check reaches every external image
reference of a Containerfile (FROM, COPY --from, RUN --mount from=), remote
ADD sources, compose service images and dev container configurations. At its
introduction two bootstrap builder instructions break it -- the
apk-installed git and the shell-form fetch -- and are named exceptions owned
by this item; the rework removes them, and if the ADD measurement fails, the
fetch is re-owned then. The tag-referenced action in .github/workflows stays
outside the gate; item-0062 already records it and owns it.
