The function asserts nothing about verification; it only emits fixtures, writing internal/verify/testdata/golden with fresh nondeterministic signatures on every run. make golden does not cover it, and under the single-switch rule a default run with the harness up would silently rewrite checked-in goldens -- so it must be reclassified as a generator rather than converted to fail-fast. Its doc comment also carries an instruction reference (instruction 5a-ii) that violates the self-contained-comments rule and falls away with the rework.

Absorbed from the item-0114 completion report (two points). First, the
coupling: the verify goldens bind to the bytes of golden/lane.yaml (UC2 treats
the lane as policy), so a lane schema change cascades into a full keyless
regeneration, and known harness behavior re-keys trusted_root.json on a cold
start -- budget all five files and gate on the set verifying together. Second,
commit shape: item-0114 bundled the forced golden refresh into the schema
commit; the regeneration doc this item writes states that such a refresh is
cleanly separable and lands as its own commit for review.

Sequencing note (added on amendment). The Makefile is scheduled for removal by
items that sit far behind this one in the execution order, so the acceptance
deliberately anchors neither the regeneration entry point nor its documentation
to a Make target. Two facts make that cheap. The tool directive is already
established in the tree -- go.mod carries a tool line for the CUE command and
the Makefile already drives go tool cue -- so this item is the first
module-local tool, not the introduction of the mechanism. And the doc-at-the-
fixtures convention this item sets is the one the executor goldens will need
later anyway, since their go test -update entry point cannot become a tool.

The two items are only cosmetically coupled. This one turns on the visibility
wall between the generator and internal/deploy; the Makefile removal turns on
how the generate-before-build edge for the uncommitted CUE-derived lane types
is preserved once make no longer expresses it. Neither decision constrains the
other, so this item does not wait.
