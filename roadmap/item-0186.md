Created by operator decision of 2026-11-06 (fork H1 of the item-0173
preparation). Operator rule of 2026-11-05: inside a lane run nothing
resolves through system DNS and every host the run reaches is declared;
strike verify declares nothing about registry identity.

Found at 44689a1: three controller-side reads inside strike run use
go-containerregistry's default transport, so they resolve through the
system resolver and trust the system roots -- the pack base fetch
(internal/executor/pack.go through registry.FetchImage), the base-SBOM
referrer fetch and the keyless trust-root fetch of the deploy
(internal/deploy/base_sbom.go). Only the deploy target carries a host and
an anchor today; the pack base and trustRootRef are bare image
references. The run's transport.Dialer offers DialPeer with a pinned
anchor and LookupHost, nothing else.

History: the lane-wide registry string (no anchor) was the engine-push tag
prefix and was removed with ADR-051 (1da3a0b); the OCI peer type was
removed with ADR-029 (d13ba71), which named a controller-pull registry
allowlist as "a distinct lane-level field, not a peer" if wanted later.
Peers stay container egress; this item adds that lane-level field.

Decided (2026-11-06): the declaration is lane-level in the endpoint TLS
shape (H2 a); the engine's own pull of step images stays out of scope,
because strike does not control the engine's resolver, and is recorded as
a known boundary (H5). Open until authoring: the anchor form for public
registries -- a pinned rootca under the existing #CertificateMode, or a
new mode (H3).

Measure before authoring (H4): the redirect targets, and their stability,
of anonymous blob GETs for the base images the tree uses (cgr.dev today).
In a run the transport dials declared hosts only, so a registry that
redirects blobs to a storage or CDN host fails the pack base fetch unless
that host is declared or not needed.

This item takes the in-run half of fork G6' from item-0173; item-0173
keeps the verify side and depends on this item.
