Introduced by the item-0049 landing run. misspell reads the identifier ADN as a
misspelling of AND and fires 38 times; the identifier is operator-ratified, make
generate emits it from an @go(ADN) annotation, and the wire field, the JSON tag
and the operator-facing error strings all carry adn, so no code edit removes the
finding and //nolint is forbidden. The run added an ignore-rule under
linters.settings.misspell with the reason in a comment.

AI-WORKFLOW.md clause 4 names a linter allowlist entry as a deferral that must
carry an owner item, which is why this item exists. Whether it is a deferral in
substance is the open question: a deferral accepts a finding about strike's own
code until revisited, while this entry contradicts the tool's dictionary about a
term from RFC 8310. If the second reading holds the entry never expires, and the
right resolution is to say so at the entry rather than to keep an item open
forever.

The narrower alternative to weigh: a path-scoped exclude-rule instead of a global
ignore-rule, so a genuine and-for-adn typo elsewhere in the tree still fails the
gate.
