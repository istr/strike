commit (2026-03-30); every bootstrap since then builds a three-month-old
strike. Blocking finding (static read; the executor confirms dynamically):

## Amendment 2026-09-14 at 7b09365: the Containerfile loses its engine stage and gains two pieces of the bootstrap proof

The sibling decision of 2026-09-14 (item-0155) removes the podman stage:
the second stage becomes a digest-pinned static base carrying the binary
and the pinned tree, and the published run line binds the operator's
engine socket instead of starting an engine inside the image. The
third-party engine image at the root of the bootstrap chain, its proc
unmask and its tmpfs storage disappear with it.

Two findings from the bootstrap review land here because the
Containerfile is this item's surface. First, the stage_0 build and the
lane's build step differ in flags (the lane disables VCS stamping, the
Containerfile does not) and in toolchain (a go.dev toolchain in the golang
alpine image versus a Wolfi-built toolchain in the lane), and neither locks
the toolchain, so a go.mod bump can make the go command download a newer
toolchain through the declared module proxy peer without a trace in the
record. Aligning flags and locking the toolchain makes the stage_1 binary
comparable with the lane-built one, which item-0160 uses as an
informational toolchain-diversity check; moving the builder stage onto
the lane's toolchain image under the cgr.dev rule would end that
diversity, so the rule and the check are traded off explicitly here.
Second, the header still documents the keyed-signing variables ADR-043
retired; the measured run line comes from item-0156.
