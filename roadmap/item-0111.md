ADR-054. The method is suspended, not retired: the discriminator, the
two-arm disjunction, the union interface and the parse-time dispatch all
survived the removal of the kubectl implementation and are reused here
unchanged. What this item builds is the act itself.

The control plane dials the cluster API over a trust-anchored TLS
connection and applies through it, in the shape ADR-051 D4 established for
the registry push: the control plane owns the act and the engine never
performs it. The manifests are read from the deploy's digest-pinned
artifacts with the SaveImage/OutputLayer/tar-buffer triple that regionSBOM
already uses, so the payload never passes through a container. Server trust
is a method field after the DeployRegistry.target pattern, not a step peer
entry, because ADR-029 reserves the peer list for container egress. The
client credential is a separate declaration from the server anchor
(ADR-007).

ADR-054 D5 left six questions open on purpose, each because it needs
measurement against a running cluster rather than reading the design. All
six are ratified before any instruction is authored here: the apply
mechanism and whether a strategy vocabulary returns; how a manifest kind
resolves to its API resource path; which mechanism carries the client
credential; where the signed statements and SBOM documents are published
for a deploy that performs no registry push, and whether such a deploy
declares a publication target of its own; the artifacts cardinality and arm
composition that ADR-051 D9 deferred to the kubernetes rewiring; and
whether the ADR-016 state captures stay container-computed once the apply
itself is a control-plane act.

The publication-sink question is carried here rather than in its own item
because it has no standing without this method: after the kubectl removal
every executable deploy is a registry push, so a push-less deploy does not
exist to need a sink.

Absorbed from the item-0114 completion report: the ratified D9 registry
rules made a registry deploy without artifacts invalid, so
internal/lane/testdata/valid_minimal.yaml grew a build step and an
artifacts map. The earlier plan to restore it as a one-step
kubernetes-method lane is void -- under every coherent resolution of the
cardinality question a kubernetes deploy needs a producing step, so a
one-step lane is unreachable. Reshape the fixture once, here, to whatever
minimal shape the ratified cardinality permits.
