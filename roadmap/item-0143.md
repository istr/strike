Address-plus-trust is declared four ways today: resolver as endpoint.#TLS, the keyless endpoints as endpoint.#HTTPS (url instead of authority, no discriminator), the OIDC issuer as a bare string beside a trust anchor, and the deploy target as #DeployRegistryTarget, which restates the #TLS field set verbatim. The kubernetes method rebuild adds a fifth. The restatement is not a design decision: the #DeployRegistryTarget comment states the reason is that gengotypes emits @go overrides verbatim, so an embedded cross-package definition would produce unqualified type names. That is a generator defect, and item-0050 already owns its repair, which is why this depends on it. Cementing a tooling workaround as schema structure is what undermines the cross-implementation reading CUE-first exists to support: a verifier that reads only the exported schema must learn four forms of one concept.

## Amendment 2026-11-22 at 210e3ca: the export of an embedding

Measured at 210e3ca, the JSON Schema export does not carry an
embedding. For endpoint.#TLS embedding endpoint.#ServerTLS it wrote an
object closed with additionalProperties false, holding the type and a
$ref to #ServerTLS, which is closed in turn and requires host and
trust. additionalProperties reads only the properties of its own schema
object (JSON Schema 2020-12, section 10.3.2.3), so the outer object
rejects host and trust and #ServerTLS rejects the type: no instance
satisfies the export. ADR-017 records the defect in its amendment of
2026-11-22.

The acceptance of this item derives the dial targets from one
definition, which needs an embedding the export carries, so this item
owns the repair: in the post-processing of the export (ADR-017,
amendment of 2026-11-20) or in how the definitions are written. Until
it lands:

- endpoint.#ServerTLS, host and trust without a discriminator, exists
  since part 3 of item-0198 and is the shape a lane registry and its
  storages hold; endpoint.#TLS restates its two fields and adds the
  discriminator instead of embedding it;
- #EngineTLS and #EngineMTLS embed #EngineServerTLS and are exported in
  the same form; item-0004 reshapes them, and the repair covers them.
