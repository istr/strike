Address-plus-trust is declared four ways today: resolver as endpoint.#TLS, the keyless endpoints as endpoint.#HTTPS (url instead of authority, no discriminator), the OIDC issuer as a bare string beside a trust anchor, and the deploy target as #DeployRegistryTarget, which restates the #TLS field set verbatim. The kubernetes method rebuild adds a fifth. The restatement is not a design decision: the #DeployRegistryTarget comment states the reason is that gengotypes emits @go overrides verbatim, so an embedded cross-package definition would produce unqualified type names. That is a generator defect, and item-0050 already owns its repair, which is why this depends on it. Cementing a tooling workaround as schema structure is what undermines the cross-implementation reading CUE-first exists to support: a verifier that reads only the exported schema must learn four forms of one concept.
