Created by operator decision of 2026-11-07 (fork F3 of the review of the
item-0186 part 2 landing): sort every object at every level in all 21
vectors, gate the form in the working-tree check, and run this item before
the remaining item-0186 work.

Found at 4ea672a: make golden rewrites five vectors without changing a
value -- assemble/empty_base_single_file.json and the four
sshknownhosts vectors -- and the operator's run reproduced exactly that
set. updateVectorBlocks decodes a vector into a map of raw messages and
re-marshals it, so the top-level keys come out sorted (expected before
inputs, while the sshknownhosts vectors were written inputs first), a
replaced block comes out in its Go struct's field order (assembleExpected
puts config_json_base64 before diff_ids, the vector the other way round),
and a block that is not replaced keeps whatever order it was written in.
The output is therefore a mix of three orders and is stable only while
neither the structs nor the hand-written inputs change; a field-alignment
lint can reorder a struct at any time.

The drift is recorded as accepted: the comment on updateVectorBlocks says
a committed vector is not expected to be a byte-exact fixed point of the
update path, and the regeneration section of test/crossval/README.md says
the diff may reorder keys without changing a value. Both go when the
canonical form lands. Each make golden since then has dirtied the same
files, and every executor gate that checks the porcelain after it has had
to restore them.

No vector relies on object key order: the Go consumers decode into maps
and structs, the attestation inputs are validated as a JSON document, and
the cases whose point is ordering carry it in arrays (multiple_peers in
reverse host order, three_captures_unordered) or in the implementation's
own sort (env_ordering), all of which the canonical form leaves alone.
None of the vectors contains a character the Go encoder escapes for HTML.

Out of scope: the value of the go_ggcr_reference block, which a toolchain
change may move by design (ADR-046); the vector contents and boundaries
themselves.
