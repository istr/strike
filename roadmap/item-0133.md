The harness Makefile is not the thin wrapper item-0097 budgets for. It carries
19 rules: 12 phony targets plus 7 file and grouped-file targets that produce all
key material. Classified against what a default test run needs, the key
generation, the stack bring-up, the Caddy root export and the TSA chain fetch
are all load-bearing, while down, clean, preflight, token, check-issuer and the
two pubkey aliases are operator-invoked only. Item-0097 as ratified budgets
check-issuer alone, yet its acceptance deletes the whole file and orphans
everything else. That mismatch is what this item resolves: this item owns the
artifact surface and item-0097 shrinks to the issuer gate, or item-0097 widens
and this item is folded into it. Choosing between those two is part of the work.

Scope boundary, ratified 2026-08-20: creation stays with podman compose. This
item removes make, openssl, curl, chmod, grep, seq, sleep, rm and the podman cp
extraction, leaving the external orchestration provider as the only remaining
tool on the bring-up path; removing that one is item-0134.

Two sub-questions are unresolved and need measurement rather than prediction
before the key generation is authored: whether Fulcio accepts an unencrypted
PKCS#8 fileca key, since a no would promote a currently-indirect pkcs8
dependency to a direct one, and whether the CT log requires SEC1 rather than
PKCS#8 for its signer key. The production transport package already generates
an ECDSA P-256 key and self-signed CA with SAN leaves, so the primitives exist.

Beware a latent trap the Makefile carries and a replacement must not reproduce:
the Caddy root is a plain file target with no prerequisites, so once it exists
make never refreshes it -- including after the caddy_data volume has been
recreated behind its back.

Amended 2026-08-26 at ae4fa89: the classification above lists eleven of the
twelve phony targets. The twelfth is conformance, and it is operator-invoked:
it drives cosign against the committed golden bundles offline, with no harness
bring-up, so no default test run reaches it. It therefore falls with the file
rather than gaining a go-native replacement here. Its end form is item-0134's
decision -- run cosign from a digest-pinned container through the engine API,
or keep it as a deliberate external-verifier exception -- and authoring that
replacement in this item would pre-empt it. What this item does own is the
handover: the three in-tree references (test/sigstore-local/README.md at the
client-version note and the whole Conformance section, and
internal/verify/testdata/golden/README.md at the independent-verification
section) are repointed to the cosign invocation written out directly, so the
independent-verifier baseline stays runnable between this item and item-0134
instead of being orphaned by the deletion.
