TestWrapArchiveAsImage_RealSymlink failed once during a full-tree run with an overlay-mount "device or resource busy" error, then passed standalone and on an immediate rerun with no code change in between. The packages that drive containers -- internal/registry, internal/container, cmd/strike, test/integration -- run concurrently under go test against the single podman engine, and their storage operations collide. The cause predates the sealing arc but the exposure grew with it: make integration now covers the whole tree, and cmd/strike became container-heavy with the live registry-deploy test. make check is the sole pre-commit gate, so a gate that turns red without a code change erodes the discipline the workflow rests on. Serializing the container-heavy packages and isolating per-test storage are both candidates; choosing between them is part of this item.
