Closes the measured duplication between the two Go-type linters: a shared
strike-named-type resolver, a shared allowlist idiom, and a shared package
loader, duplicated across two modules. More deeply, the conversion-ownership
check is a subset of the conversion facts the flow extractor already emits, so
it folds in as a fact kind emitted from the one traversal rather than a second
detector.

Entrypoint direction, resolved against the golangci-lint source rather than
assumed: the default issue-processor chain drops every issue whose file is not
a .go file, so analyzers that position diagnostics on Markdown -- the sibling
ASCII and ADR-index gates -- would pass silently as a custom plugin. That
removes the reason to build plugin machinery for the Go-type gates alone. The
tools instead become module-local main packages in the root module, declared
through tool directives and invoked as go tool, which is the precedent
ADR-050 set for the CUE CLI and item-0120 set for the golden generator. No
make, no shell, no second orchestration layer.

Executed in slices. The first merges the two Go-type tools into tools/linttype
behind one multichecker with three analyzers and a separate -report path. The
second measures what the root lint profile reports over the previously
unlinted tool code. The third brings the extractor under the profile's
complexity limits, ahead of the fold rather than after it, so the fold needs
no exclusion for a finding it would otherwise carry. The fourth moves the
document gate's file reads onto os.Root per the path-confined-io rule. The
fifth drops go/analysis from that gate: the analyzer shape existed for the
plugin route the second slice measured away, and it was keeping two
package-level once-guards alive to suppress the repeat calls a per-package
driver makes to a tree-wide check. The sixth folds linttype and lintdocs into
the root module, skips the tools tree in the extractor so a measuring
instrument does not measure itself, renames lintdocs to lintdoc so the linter
family reads lintdoc, linttype, lintcue, and replaces the three Makefile
targets.

Naming follows the prefix shape item-0094 ratified for lintcue: the tool is
linttype, the target is lint-type. docs/ADR-049 keeps the historical name
linttypeconv in its decision prose, because ADRs are append-only.

## Final summary

Landed across six slices, ending at commit f7b4764. linttypeconv and linttypeflow merged into tools/linttype: one multichecker entrypoint (ConvOwnerAnalyzer, FlowAnalyzer, StutterAnalyzer) over one extractor traversal, with conv-owner expressed as a fact kind from that traversal rather than a second detector, and strikeNamed/allowed/packages.Load each existing once. The -report survey is preserved as a separate code path over the same walkFile extractor. lintdocs was renamed lintdoc, reduced to a plain command, and confined to os.Root. Both linttype and lintdoc are now root-module packages declared as tool directives and invoked via go tool, so no lint gate builds a binary into .build. The extractor's tools-tree self-exclusion was found to cover only the gate path (gate.go runFacts) and not the survey path (flow.go collect()); both now share one skipPackage predicate, verified by a fresh -report survey showing zero tools-prefixed facts. All eight acceptance_intent clauses re-verified against the tree at f7b4764 before retiring.
