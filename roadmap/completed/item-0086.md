Register row R-34, adjudicated in item-0072 as D1 per rulebook RB-05 and ADR-049 (1). The target forms are already modelled: AbsPath carries the socket path, Authority carries the tcp host:port. The scheme prefix is the type switch, not a missing type, so no contract definition is added -- the engine address never reaches the wire (contract/endpoint/engine.cue attests type and cert identity, never an address).

Amended 2026-08-22 after a code and ADR check: the accepted scheme set narrows
to unix:// and https://, and tcp:// is dropped. tcp:// was a transport token,
never a protocol choice -- apiBase already emitted an https base URL for that
arm unconditionally, the engine TLSConfig floors at TLS 1.3, internal/container
holds no InsecureSkipVerify, and an http:// address already fell into the
unsupported-scheme arm, so a plaintext engine connection is unreachable by
construction. No ADR ratifies the token; it is inherited Docker and Podman
CONTAINER_HOST convention, while the attested vocabulary has said unix / tls /
mtls all along (contract/endpoint/engine.cue, ADR-012).

Admitting only unix:// and https:// makes the address grammar state what the
code already guarantees, at the single place this item creates, and lets the
parser reuse the endpoint URL parser so internal/container owns no address
grammar of its own -- the shape contract/endpoint/address.cue already prescribes
for service endpoints, where the https regex makes a plaintext base a parse
error rather than a runtime rejection. The target type of the network form
follows: endpoint.Address, not endpoint.Authority, because Authority is the
packed projection of Address and carries no URL projection of its own.

Breaking change to the documented CONTAINER_HOST grammar, accepted pre-beta; a
CONTAINER_HOST shared with podman-remote over TCP would need a second variable.
The engine socket path stops at the transport signature: the DialUnixSocket
parameter retype is deferred to item-0079, which owns the env-derived host-path
domain.

## Final summary

Landed in commit ecf7dd4: parseEngineAddress consolidates the CONTAINER_HOST parse in internal/container/transport.go into a single unix-or-https discriminator; newHTTPClient, apiBase, and NewFromAddress all take the parsed engineAddress value; tcp:// dropped from the accepted grammar; AGENTS.md, docs/DEVELOPMENT.md, README.md updated to match; make check green.
