Follow-up from the item-0166 part 2 run of 2026-11-04: the golden trusted_root.json goes stale on every harness recreate, because the TSA mints a fresh signing chain per start, so verifying the live bootstrap deployment with cosign needed the golden root with its TSA chain swapped by hand.

## Amendment 2026-11-05 at 060225f: unparked ahead of item-0173

By operator decision of 2026-11-05 this item leaves the parked arc and
runs before item-0173, which now depends on it. No integration test in
the tree reaches a full strike verify verdict on live bundles: the golden
trusted root goes stale with every harness start, and verify takes its
trust root only from the lane (inline or keyless.trustRootRef) or from
--trust-root-ref, never from a file. A live trust root published as a
digest-pinned image lets item-0173's integration test verify end to end
(push under the registry token, read-back with and without a credential,
signature verification) and gives the trust-root read a live exercise.
The pre-cut release of item-0062 verifies against the harness chain as
well, so a live trust root is needed before that item in any case.

The goal is sharpened from the cosign recipe to the trust-root image. The
cosign conformance recipe on live bundles stays in this item only if it
is small at authoring; otherwise it becomes its own follow-up item then.

## Amendment 2026-11-05 at c8c9de9: no file on disk, cosign stays with item-0007

Authoring found three things the acceptance above did not foresee; the
operator decided them on 2026-11-05.

The assembly existed three times, not twice: the live keyless test in
internal/deploy carried its own copy beside tools/gengolden. The
generator, that test and the registry-deploy itest now share one
function in internal/testutil. It takes the Fulcio HTTP client from the
caller, because the deploy package's internal tests import testutil, so
testutil cannot import deploy.

The live document is not written to disk. lintdoc walks the whole
working tree, ignored files included, and a trusted_root.json carrying
the per-start TSA chain would fail its DER-blob gate on every machine
that runs the harness; the chain rotates, so it cannot be allowlisted.
The document exists in memory and in the harness registry only.

The cosign verification of live bundles is not small: cosign exists
only as an image (ADR-055 D2), and the harness registry is private. It
is not split into a new item, because item-0007 already owns exactly
that check; item-0007 now depends on this item.

Two smaller decisions: the image keeps the plain form the existing
trust-root round-trip test pushes (one OCI layer, no artifactType), and
the repository is the fixed strike-itest-trust-root, written by digest
without a tag. FetchTrustRoot cannot reach the private harness registry
at this anchor, because it reads anonymously under the system roots, so
the read through it belongs to item-0173; this item reads back under
the registry token. The execution profile is raised because acceptance
includes live verification against the running harness.
