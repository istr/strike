Surfaced by item-0119: the retargeted mediator integration test was the
first test in the module to complete a proxied round trip and then await
Serve while its client was still connected, and it hung to the go test
timeout. The test-side ordering was corrected there; this item owns the three
defects the hang exposed underneath. They are one item because each fix on
its own leaves a path where the others still bite, and the acceptance is one
property: a step that ends, by success, failure, or deadline, leaves no
capsule goroutine and no container behind.

Defect one, the root: the mediator's proxy phase ignores the serve context.
The two copy directions end only when their source reaches EOF, nothing
closes either connection on cancellation, and the accept loop waits for every
proxied connection before Serve returns. The Close doc comment promises the
opposite ("cancel the Serve context to stop them"). No ADR chose drain
semantics; the function is unchanged since its birth commit. Fix: close both
sides of a proxied connection when the context is done, so a blocked read
returns and the existing closed-connection mapping turns it into a clean
return. Regression test: the item-0119 choreography, hermetic, with a bound
on how long Serve may take to return after cancel. In the same function the
fix touches, capsule Stop holds its state mutex across the serve-group wait,
so today that lock is held for as long as defect one blocks; it is the one
lock in the module held across an unbounded wait, and the fix should not
leave it that way.

Defect two, the engine: a step deadline aborts the wait request, not the
container. On a wait error the run primitive returns without the container
id and without removing it, so a caller cannot clean up even in principle,
and the deferred remove on the run path reuses the expired step context, so
its DELETE fails at once. Fix: a container the engine created is removed by
the engine on every error path, on a context that is not the one that just
expired; the run path's deferred remove uses such a context too. The removal
endpoint already forces, so a live container is killed, not skipped.

Defect three, the exit: a failed run leaves through a fatal log call, which
skips the deferred capsule stop and trust-volume removal. Today that is
what keeps the run path from hanging on defect one, and it also means a
failed run never cleans up. Once one and two hold, the exit path can tear
down deliberately and still exit non-zero.

Where it hurts now: the deploy path defers capsule Stop around the container
run per unit, so a capture or kubectl container that hits its step timeout
while holding a mediated connection blocks the lane inside Stop until that
connection closes on its own, and the timeout fires precisely when such a
connection is expected to be open. The run path is safe only because every
container has exited and been removed before the lane-end Stop, and because
failure exits without stopping at all. A remote upstream that ignores the
half-close sent after the client side closes is the same hang from the other
direction.

Open question: whether the fatal exit in defect three should become an
ordinary error return through the run command, or keep the fatal call and
run the teardown explicitly before it. Either satisfies the acceptance; the
first is the smaller surface once the defers already exist.

## Final summary

Landed as b28a8b2. The mediator proxy is bound to its serve context: cancellation closes both connections, so a blocked copy returns and Serve returns promptly even with an in-flight proxied connection open, and the Close doc comment now describes that. Capsule Stop claims the state transition and releases its mutex before the serve-group wait, so one connection that will not close no longer blocks the lifecycle. The engine force-removes a container it created but could not carry to a clean exit, on a context detached from the one that just expired, and returns an empty id afterwards, so a non-empty id names a container that exists; the run path's deferred removal is detached for the same reason. cmdRun is fatal-free and returns its error to main, so capsule stop and trust-volume removal run before a failed run exits non-zero. Three regression tests cover the properties: mediator cancel with an open proxy, engine wait aborted forcing a remove, and a deploy capture unit that hits its step deadline while holding a mediated connection. The mediator integration test lost its drain workaround. Production mutex count unchanged at seven; the lock-free conversion arc was not entered. Two instruction defects surfaced and are recorded in the commit body: an unlisted same-package test caller of allocateMediatedPorts, and an insertion anchor specified as a bare func line that detached the runContainer doc comment.
