Three tests skip silently when STRIKE_CLOUDFLARE_DOT_FINGERPRINT (and, for the mediator test, STRIKE_CLOUDFLARE_HTTPS_FINGERPRINT) is unset, while their own doc comments claim they fail fast -- the comment and the code contradict each other. Complication: the Cloudflare fingerprint rotates and has no harness-local source, so a plain Fatalf would make the suite fail on every fresh machine. The harness now carries a CoreDNS DoT resolver with a committed-key-free pinned certificate (pki/resolver.crt), which is a candidate replacement anchor; whether the public-Cloudflare coverage is kept alongside it is part of this item.

## Final summary

Retargeted all three integration tests at the local sigstore harness. The two transport tests dial the harness DoT resolver on 127.0.0.1:8853; the mediator test mediates a connection to the harness registry endpoint. Each acquires the harness through RequireEngine plus RequireHarness, so a stopped harness is recovered and a missing one fails fast with the STRIKE_INTEGRATION=0 hint. Trust is a CA bundle on both hops: pki/resolver.crt for the resolver, the exported pki/caddy-root.crt for the mediated peer. The bind-mount documentation was corrected to explain that single-file mounts bind the inode and therefore survive only on in-place truncation, not file replacement; the first attempt at this change failed due to an inverted understanding of that behavior. STRIKE_INTEGRATION=0 is now the single opt-out for every integration test in the module. Commit b85981c.
