Scope note. This item was originally scoped as a typing change ("bind the
positive-case inputs to the real lane schemas"). Grounding at the anchor found
two vector sets that do not perform the cross-implementation validation they
exist for, and the operator ratified repairing them here rather than deferring:
the construct must remain, and must become logically sound, or crossval has no
reason to exist. The typing half is unchanged and still lands.

Why the ssh known-hosts vectors are broken. RenderKnownHosts renders the lane's
synthetic front host key for every declared ssh peer (ADR-038 D5); the peer's own
declared key deliberately never reaches the container. The vectors expect the
peer key instead, which is the behaviour from before that decision, and the
hand-written unit test asserts the opposite explicitly. They survive only because
no test executes them -- the schema validates them, nothing runs them -- and the
open peers list hid the field-name drift from the endpoint contract at the same
time. Their key values are not decodable base64 either. The front key is a second
input the vector schema does not model at all, so the boundary cannot be
expressed without adding it.

Why the assemble vector is not reproducible. Its base image is named by a
library-bound sentinel that only Go resolves, and its expected manifest digest
commits to a gzip-compressed layer blob. Deflate output is not specified by
compression level, so no independent implementation reproduces it. ADR-046's
second amendment already measured and ratified the general fact: the same
uncompressed content through a different encoder yields a different blob digest
and a different manifest digest, while the config blob and the rootfs diff-ids
survive unchanged. The expectation split follows that ratified finding rather
than inventing a new rule.

Reproducibility audit of the other three boundaries. SpecHash reads only Args and
Env from the step and is otherwise a sha256 chain over strings; StateDigest is a
sha256 over length-prefixed fields whose encoding is stated normatively in its
doc comment; ValidateAttestation is schema unification. All three are complete
and reproducible, and are untouched apart from the typing.

Boundaries of this item. The spec-hash and assemble map-key domains are not
settled here: item-0078 owns the spec-hash keying doc drift, the always-empty
source-hash parameter, and the dotted-ref keying. The capture snapshot fields in
the deploy package are typed by item-0080 (register row R-17), so the CUE side
leads here and the Go fixture follows there. Neither is a deferral of this item's
own work; both are questions another item already owns.

Recorded, not repaired here. primitive.#Base64 admits strings whose length is one
more than a multiple of four, which can never decode; tightening it would touch
every #HostKey in the contract and needs its own ratification. The exported JSON
Schema is a lossy projection of the CUE, so a consumer validating only against
contract/attestation.schema.json can still diverge from the CUE-validating path;
ADR-017 names that gap as the reason the vectors exist and this item does not
close it.

## Final summary

Crossval closed: inputs bound to the contract types, the AssembleImage base stated in wire terms over a spec-conformant OCI base, expectations split into a normative block and a non-normative go_ggcr_reference block, the RenderKnownHosts front key made a declared input with byte-exact comparison, fixture structs typed where that removed a conversion, README and ADR-017/ADR-046 amended. Deferred with named owners: the spec-hash and assemble map-key domains (item-0078), the capture snapshot Go fields (item-0080), the primitive.#Base64 length rule (recorded, unowned).
