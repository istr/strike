The shape is RFC 8310's full direct configuration (section 7.1): the lane
carries an authentication domain name and an IP address for the resolver, both
obtained out of band. The ADN is the only server identifier -- section 3
excludes IP addresses from that role -- so the IP is the routing target and
nothing else, and the certificate is verified against the ADN as section 8.1
requires: the whole chain per RFC 5280, the reference identifier matched in
subjectAltName only, never in the Subject. Go satisfies the subjectAltName half
because it dropped the legacy CommonName fallback, not because anything here
configures it; that is worth an assertion rather than an assumption.

That is why the trust anchor narrows to a CA bundle. Section 6.6 admits an ADN
from a section 7 source or an SPKI pin set, and a digest over the leaf
certificate is neither, so certFingerprint cannot authenticate this endpoint.
The anchor keeps the discriminated shape a peer declares, which makes the
resolver's anchor set a strict subset of a peer's rather than a different
mechanism. The narrowing is recorded on ADR-028, whose parity clauses committed
the two-member vocabulary; certFingerprint stays available everywhere else.
The system trust store is not an alternative either: ADR-021's deferral is in
force.

The IP literal is lax in CUE and binding in Go, the split ADR-027's CUE-first
principle states and ADR-039's amendment describes for exactly this field: a
complete IPv6 regex is impractically large, so the schema shape is loose and
netip.ParseAddr at the validate step is the acceptance criterion. The port
default lives in Go for the same reason the address projection does -- a CUE
default arm was measured and rejected.

Conformance is the whole point of the item, so no MUST is carried out of it.
Where each lands:

- No fallback from Strict to Opportunistic during a query (5.1): structural,
  there is no opportunistic path to fall back to.
- Authentication information known before connecting, and a connection aborted
  when no verification mechanism succeeds (6.6): the schema makes adn and the
  bundle required, and a failed handshake is a returned error, never a
  downgrade.
- No query before an authenticated server is available (6.6): the run-start
  probe already sequences this, and every later lookup opens its own verified
  connection.
- Full path verification and subjectAltName-only matching (8.1): standard chain
  verification against the declared bundle, with the reference identifier
  asserted.
- RFC 7525 adherence except for the version, TLS 1.2 or later only, and no TLS
  compression (9): the floor and the bounded cipher set are in place per
  ADR-032; the remaining RFC 7525 items are an audit of the dial path, and any
  gap found there closes here rather than becoming a follow-up.
- Session resumption without server-side state (9): the only MUST that needs
  new code. The client session cache is state, and package-level mutable state
  is forbidden, so it belongs to the dialer value that already owns the
  declaration. Open question for ratification: whether a cache carrying an
  internal lock sits comfortably beside ADR-052, given that the lock is the
  standard library's and not strike's.
- Raw public keys (9): the same sentence that requires them forbids a client
  without an SPKI pin set from indicating support. strike holds no SPKI pin
  set in any reachable configuration, so the only conformant behaviour is
  silence, which is what the standard library already does. Discharged, not
  deferred -- implementing an unusable capability would be dead surface.
- The captive-portal alert (6.6): conditional on bootstrap techniques such as
  dnssec-trigger, which strike does not use. The antecedent never holds.

SHOULDs that stay out, each with its reason: DANE and the option that limits
authentication to it (8.2, 11) need a DNSSEC-validating stub the standard
library does not offer; EDNS(0) padding and the edns-client-subnet privacy
election (11.1) need the resolver's message construction replaced; False Start
and the cached information extension (9) are latency work with no bearing on
the trust chain. SPKI pinning is out for a different reason: it is conformant
but inherits the HPKP failure mode.

Open before authoring: how the generated types come out. An earlier measurement
assumed a bare path field for the anchor and does not carry over to the
discriminated form, so the generator outcome is unmeasured and has to be taken
in a throwaway worktree rather than predicted.

Known consequence: the golden lane fixture must change, and the seal covers its
raw bytes, so the four generated keyless fixtures are regenerated against a
running harness. The golden set's own rule puts that regeneration in its own
commit beside the change rather than inside it (item-0131 is the same
mechanic).

## Final summary

The lane's DoT resolver is now its own endpoint type: an authentication domain name, an IP literal, an optional port defaulted to 853 in Go, and a CA-bundle anchor. strike routes to the IP, sends the ADN as SNI, and verifies the whole certification path against the ADN in subjectAltName only; certFingerprint is rejected on this endpoint and stays available on every other. Every RFC 8310 MUST binding a DNS client is met or discharged with its reason, including session resumption without server-side state, which lives on the dialer value and is pinned by a test that fails closed if the cache is dropped. The attestation gained dialedIP and lost serverName. The forced keyless golden regeneration landed separately as item-0131, per the golden set's own commit rule, so this item is complete only together with it. Landed as 06ab773.
