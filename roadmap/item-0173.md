Carved out of the ADR-058 preparation by operator decision of 2026-10-30 (Fork H): item-0166 authenticates the write side and removes the ambient keychain; the read side's anchor and credential threading is this item, so the push item stays bounded. Measured at 1344ed5: Azure Container Registry invalidates its referrers listing on write and serves it fresh afterwards, Google Artifact Registry lists only descriptors with an explicit artifactType; the HEAD cross-check is the registry-independent guard. Runs after item-0166 and before item-0062.

## Amendment 2026-11-03 at 13f40f7: an anonymous read never reaches a manifest under bearer.oidc

Measured on 2026-11-03 at 876fb38 against zot 2.1.22 under bearer.oidc
with the realm on the registry's own host: after the 401 ping,
go-containerregistry performs the token exchange at the challenge realm
(GET /v2/token with scope and service), which zot answers 404, so an
anonymous read fails before any manifest or referrers request. The
harness repositories are private from item-0166 on, and item-0166's
integration tests read back with the registry token. This item's read
paths need the declared credential to reach the harness at all;
"anonymously where nothing is declared" reaches only registries that
admit anonymous reads.

## Amendment 2026-11-06 at 6a0daac: the in-run reads move to item-0186

By operator decision of 2026-11-06, the controller-side registry reads
inside strike run -- the deploy's base-SBOM referrer fetch and trust-root
fetch, and the pack base fetch -- are declared and dialed through the
run's resolver in item-0186, which this item now depends on. This item
keeps the strike verify side, where nothing is declared about registry
identity.

## Amendment 2026-11-06 at 47b4bc1: the redirect rule protects the declared credential

The redirect rule decided for this item on 2026-11-04 and 2026-11-05 --
a request carrying the declared credential fails closed on any
redirect, on any host, push included; an anonymous read follows
redirects -- keys on the credential the operator declares, the registry
token strike presents as the bearer (ADR-058 D2), and never on the mere
presence of an Authorization header. A token a registry's realm issues
to an anonymous read is not such a credential. Measured at 584b66a: an
anonymous pull from cgr.dev carries a realm-issued bearer on every
manifest and blob request, and every blob read is redirected to a
storage host. How a registry authenticates its storage is outside
strike's influence; what is protected is the operator-side credential.
An anonymous read follows the redirect rules of its context: inside a
run those of item-0186, in strike verify the anonymous path.

## Amendment 2026-11-08 at cdd04f3: the decisions of the item preparation

Operator decisions of 2026-11-04 to 2026-11-08, in the order they bind
the work.

The credential. strike verify reads no lane secret: a registry token
reaches it only through `--registry-token` (a source, `env://NAME` or
`file://path`, never the value), and without it every read is anonymous,
through the system resolver and roots. With the token, UC2 takes the
anchor and the audience check from the registry deploy `--deploy-step`
names (optional when the lane has exactly one; otherwise verify fails and
says which flag selects), UC1 takes the anchor from `--registry-ca`
(`file://` PEM, required with the token in UC1, refused in UC2). The token
is checked against the fixed lifetime bound, and in UC2 its audience must
not contain the oidc audience. The trust-root read carries the token only
when its host is the target's host. In a lane run the registry token of
every deploy target is read and checked once at run start, and every
in-run connection to a target authority carries it; deploy targets that
share an authority declare the same anchor and token. One round tripper
sets the bearer for the declared authority only and refuses every request
that results from a redirect, push and read alike; an opt-in for a
registry that redirects credentialed reads is item-0174's to decide. The
HEAD cross-check of the item's first text is replaced by the
read-after-write below; base-SBOM and trust-root reads inside a run moved
to item-0186.

Consistency. After attaching the statement bundles the deploy confirms
that the payload and every attached referrer answer a manifest HEAD and
that the filtered referrers listing of each attached artifact type holds
every attached digest, through the credential transport. The referrer
read retries with exponential backoff up to a fixed bound of sixty
seconds, then fails closed; the deploy fails without rollback (nothing is
tagged; only the register commit makes a candidate a release) and names
registry, subject and missing digests. strike verify shares the retry and
waits only for the required layers (sealed, and engine-dependent unless
--no-engine-trust), never for an optional bundle. The wait is an
interruptible wait injected into the retry, so no test waits; there is no
sleep. Microsoft documents eventual consistency for geo-replicated ACR
only; the referrers cache measured on 2026-10-31 is undocumented.

Cut. Part 1a: the credential transport, the run-start token, the
per-authority rule. Part 1b: the wait, the retry and the read-after-write.
Part 1c: strike verify's flags, its credential transport, the retry
predicate and the end-to-end integration test against the private harness
registry. Part 2: a public harness registry without authentication, a
test-side copy by digest, and anonymous integration tests. Execution
profile large/deep for every part.
