Carved out of the ADR-058 preparation by operator decision of 2026-10-30 (Fork H): item-0166 authenticates the write side and removes the ambient keychain; the read side's anchor and credential threading is this item, so the push item stays bounded. Measured at 1344ed5: Azure Container Registry invalidates its referrers listing on write and serves it fresh afterwards, Google Artifact Registry lists only descriptors with an explicit artifactType; the HEAD cross-check is the registry-independent guard. Runs after item-0166 and before item-0062.

## Amendment 2026-11-03 at 13f40f7: an anonymous read never reaches a manifest under bearer.oidc

Measured on 2026-11-03 at 876fb38 against zot 2.1.22 under bearer.oidc
with the realm on the registry's own host: after the 401 ping,
go-containerregistry performs the token exchange at the challenge realm
(GET /v2/token with scope and service), which zot answers 404, so an
anonymous read fails before any manifest or referrers request. The
harness repositories are private from item-0166 on, and item-0166's
integration tests read back with the registry token. This item's read
paths need the declared credential to reach the harness at all;
"anonymously where nothing is declared" reaches only registries that
admit anonymous reads.

## Amendment 2026-11-06 at 6a0daac: the in-run reads move to item-0186

By operator decision of 2026-11-06, the controller-side registry reads
inside strike run -- the deploy's base-SBOM referrer fetch and trust-root
fetch, and the pack base fetch -- are declared and dialed through the
run's resolver in item-0186, which this item now depends on. This item
keeps the strike verify side, where nothing is declared about registry
identity.
