ADR-034 enumerates two moments, wrapping an output and mounting an input, and derives the rejection of absolute symlink targets structurally from the mount model: no strike mountpoint is the container root, so an absolute target can never resolve within one. Item-0122 unified pack file inputs onto the same containment routine, which was the last site still applying the blanket symlink rejection ADR-034 had replaced. That completed a migration rather than deciding anything new, but it left the site unnamed and the derivation misleading, because a pack layer is composed into a rootfs whose root is exactly the container root. Read literally, the derivation suggests absolute targets are harmless in a layer. The opposite is true: an absolute target makes the artifact's meaning depend on whatever is composed alongside it, which its own digest does not account for, and the escape surface is the whole rootfs rather than one mountpoint. The reason that holds everywhere is the one ADR-034 already used to reject the closed-union-mount alternative: containment must be decidable from the producing element alone, or the same artifact is contained under one consumer and escaping under another. Mount and layer are two mechanisms for fusing independently-digested elements into one filesystem view; the containment domain is the element. The implementation already behaves this way, evaluating containment on the producer's own coordinates before re-rooting. One consequence worth recording in the same document: nothing checks the reverse direction, a symlink in the digest-pinned base image lying on the path where a pack layer lands. That composition is deterministic and fully accounted for by the published digest, so it is a lane-authoring hazard rather than a soundness gap, and the explicit parent-directory entries the unified path now emits make it less runtime-dependent than before.
