The workflow documents are shaped by a constraint that is remembered rather
than enforced. AI-WORKFLOW.md states that both imperative files are read whole
at every anchor and therefore stay under the read-at-once limit, and it draws
the right consequence -- a rule that grows a backstory sheds the backstory to
the concept paper instead of growing in place. What it does not state is the
number, so no reader and no gate can check whether a file still fits.

Measured at 23e13760c9ff02b4de46227f03275c13196655f1, against the
16000-character single-read size of the agent file viewer: AI-WORKFLOW.md 14532,
AGENTS.md 15948, AI-ORCHESTRATION.md 15977, DESIGN-PRINCIPLES.md 16032. Two of
those sit within half a percent of the ceiling and one is already past it. One
added sentence in AGENTS.md crosses it.

Crossing it fails silently and selectively. The viewer truncates from the
middle, so a file over the limit still opens with a plausible beginning and a
plausible end; what disappears is the middle, which is where a long imperative
document keeps its specific rules rather than its framing. An agent that read a
truncated AGENTS.md has no signal that it did.

This is the project's own "enforcement is structural, not discretionary"
applied to its own instructions. A size ceiling that lives in one document's
prose as an unnamed limit is exactly the discretionary form that principle
rejects everywhere else.

Scope decision: the gate covers the documents that declare themselves read
whole -- AGENTS.md, which opens by instructing the agent to read the entire
file, and AI-WORKFLOW.md, which says so of both imperative files. Both are
under the limit at the anchor, so the gate is green when it lands and belongs
inside make check rather than beside it as a stand-up-red target. The set is
named in one place so that adding a document to it is one edit, not two.

Open question for ratification: AI-ORCHESTRATION.md and DESIGN-PRINCIPLES.md
are lookup documents by AGENTS.md's own classification, not read-fully
contracts, yet both sit at or over the ceiling and both are in practice read
whole by the analysis lane. Including them would stand the gate up red on
DESIGN-PRINCIPLES.md, which is a separate finding with a separate fix; the
default above keeps the two concerns apart.

Adjacent finding, not this item: DESIGN-PRINCIPLES.md is 32 bytes over the
limit, and its stale system-CA clause -- the one ADR-021, ADR-037 and ADR-041
corrected on their own axes on 2026-08-31 -- sits at 43 percent into that file,
inside the region a middle truncation drops first. Whether the two facts are
connected is a hypothesis, not a claim; the stale clause is a defect either way.

The constant is a property of the harness, not of strike. It moves when the
tooling moves, and a number recorded without that caveat becomes a rule whose
reason has evaporated -- which is how this constraint reached its current state.
The comment on the constant is therefore part of the acceptance, not decoration.

Sequencing note: item-0093 makes this gate a plain command in the root module,
invoked as go tool lintdoc. A new tree-wide check is one more call in main
rather than a third analyzer with its own once-guard, so this check no longer
needs to land before that work to avoid being written against two hosts.
