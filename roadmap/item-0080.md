Register rows R-01, R-08, R-09, R-11, R-17, R-30, R-31. Forks A and B are ratified (both option 1). Fork A: the unit key is a comparable value struct CapsuleUnit{Step primitive.Identifier; Capture primitive.Identifier}, empty Capture meaning "the step itself", used directly as the comparable map key, as the constructor parameter, and rendered for display/logs by one owned method; both captureKey twins and the "capture:<step>:<capture>" string protocol are removed and stepPorts becomes map[CapsuleUnit]HostPorts. It is accepted as in-process identity / disjunction glue, a hand-written comparable struct, not a CUE schema gap. Fork B: the canonical host is endpoint.CanonicalHost (hand-written, concept tier) with the single constructor Canonicalize(primitive.Host) (CanonicalHost, error); the mediator peer map, resolver allowlist, and ephemeral-CA cache key on it, while QueryRecord.QName stays string by design (untrusted wire name from container DNS packets); the linttypeconv M3 allowlist deferral is retired with this item as its owner. This is the highest-judgment item of the program; the capture-composite domain fact (retrospective 4.1.1) is the reason the unit key is a ratified design, not an executor discovery.

Amended after a whole-strand read of mediator, peer and dial. Two additions,
both inside this item's existing charter rather than new work. First, the
upstream-lookup closure is declared as three structurally identical named
function types (capsule.UpstreamLookupFunc, mediator.UpstreamLookupFunc, and a
third named in a mediator comment that does not exist), converted between at the
capsule-to-mediator seam, and carrying the name as a plain string where the
canonical-host type applies; that is the same duplication class as the
canonicalize and ssh-target twins already listed. Second, Fork B keys the peer
map on the canonical host, which makes two peers declared on the same host with
different ports collide as a duplicate; the collision follows from SNI dispatch
having no port to dispatch on, and needs to be a stated consequence rather than
a surprise at construction time.

Third addition from the same read, and the reason Fork B's provenance rule
needs restating on the TLS side: after the peer-map lookup succeeds, the
mediator still resolves and records the container-supplied SNI string rather
than the declared host it just matched. The two are equal by construction
today, since the map key is the canonicalized declared host and the lookup hit
proves the canonicalized forms match, so this is a provenance inversion rather
than a hole -- but the DoT query and the observed-peer key both derive from
container input while the lane's own typed value sits one field away. The SNI
sent upstream is a separate matter and stays the client's, which ADR-028 fixes
as SNI-preserving; this is about which value is program state. It is the same
distinction Fork B already draws when it keeps QueryRecord.QName a plain
string.
