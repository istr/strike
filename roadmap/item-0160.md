The two checks are the cross-control-plane and the strike-free halves of the
reproduction matrix. The commit gate's build step is already a plain go build
in a digest-pinned Go image orchestrated by the released strike as a sibling
(item-0063), so the cross-control-plane half costs one pack step and one
recorded digest, not a second pipeline. With one topology in the tree, the
engine diversity of this check comes from the two hosts -- the operator's
endpoint and the forge runner -- not from a nested engine; running both
halves on one machine proves less, and the release procedure says so. The
strike-free half replaces ADR-009's current advice that a distrusting
operator run the bootstrap locally, which still requires trusting strike.
The stage_1-versus-lane binary comparison is a bonus: the Containerfile
builds with the go.dev toolchain of the golang alpine image and the lane
with a Wolfi-built toolchain, so equality at matching versions is agreement
between two independently built compilers of the same version, the cheapest
form of toolchain diversity available; it stays informational until
item-0062 aligns flags and versions, and it is lost if item-0062 moves the
builder stage onto the same toolchain image the lane uses -- that trade is
named there.

## Amendment 2026-10-29 at 02f3c00: ADR-057 fixes the direction

ADR-057 D4 keeps ADR-009 C2's two hosts and two control planes and fixes
the direction: the endpoint reproduces the forge, and the approver signs
only after that reproduction. The cross-control-plane, cross-host check of
this item reads in that direction. While pre-beta builds run on the
endpoint (operator decision of 2026-10-29), both sides run on one host,
which this item already states proves less.

## Amendment 2026-11-08 at 71da092: toolchain diversity moves into the reproducedBy gate

Operator decisions of 2026-11-08. item-0151 moves the bootstrap
Containerfile's builder stage onto the lane's Go toolchain, so the
stage_1-versus-lane comparison stops being agreement between two
independently built compilers, and the last sentence of the amendment of
2026-10-31 no longer holds. The diversity moves to where it gates every
bootstrap run instead of informing a release: the lane's second build,
build-binary-2, runs in the official golang image -- the go.dev release
toolchain on a Debian base, pinned by digest at the Go version of the first
build -- so the reproducedBy gate compares binaries from two independently
built compilers. A minideb image with the distribution's Go package was
considered and rejected: the distribution patches its Go package and lags
upstream, and the image would have to be built with a package manager. The
official image is deliberately not from cgr.dev; the change departs from
ADR-055 D3's rule by name and records that in a dated note on ADR-055. The
gate requires a Wolfi-built and a go.dev toolchain of one version to build
byte-identical binaries; item-0151's measurement reports whether they do,
and the answer is carried here. The stage_1-versus-lane comparison stays, as
a check of the Containerfile build against the lane build.

## Amendment 2026-11-08 at 7dbd1f7: the toolchains differ, measure then decide

item-0151's measurement at 0aa7b9c answers no: with the lane's arguments, each
toolchain reproduces its own binary, and the Wolfi-built go1.27.3 and the
go.dev go1.27.3 build different binaries, differing from byte 24 on. The
recorded build settings show three differences: GOAMD64=v2 against v1, a
Wolfi-only chainguard_go_package setting, and -ldflags recorded by one
toolchain only. The Wolfi toolchain carries a go.env that sets GOAMD64=v2
and GOTOOLCHAIN=local, and the image sets GODEBUG; every image composed from
it inherits the go.env. Two of the differences live in the binary's build
information, so pinning GOAMD64 alone is not expected to close the gap.

The decision of 2026-11-08 that build-binary-2 runs in the official golang
image is suspended and becomes a fork, measure then decide: pin GOAMD64 for
both builds and measure what remains; then choose between independent
toolchains whose residual differences the comparison is defined to ignore,
toolchains made to agree byte for byte, or giving up the cross-toolchain
comparison in the reproducedBy gate. The acceptance intent above is restated
to match; the fork is settled before this item is authored.
