Resolved to option B (dogfooded strike lane), 2026-07-11: the gate is a strike
lane doing the work with the forge as status reporter only, not a minimal
GitHub Actions run of `make check` verbatim. Option A was the fast path but it
cements the Makefile as the CI entry point; B is the posture-consistent path
AND the orchestration substrate that lets the whole build-toolchain arc retire
the Makefile (item-0096 deletes the file against this lane). Choosing B here is
what makes full Makefile elimination a beta prerequisite rather than a
post-beta upgrade.

Two grounded dependencies carry over: item-0016 presupposes a CI to fail
("fails CI rather than relying on review"), so this item is its substrate and
should land before or with it; and the raw coverage total includes generated
code that the 100 percent target in docs/DEVELOPMENT.md excludes, so the
ratchet pins the raw metric for simplicity, and any target-versus-actual
comparison needs a separate generated-code-excluded measurement.

Sequencing: leads the build-toolchain Makefile-elimination chain -- the lane
must exist before item-0096 can delete the aggregate `make check` into it.

## Amendment 2026-09-05 at c01be87: re-derived against ADR-055

Struck from the text above: the claim that this lane is "the single check
orchestration that replaces the aggregate make check" and that item-0096
retires the Makefile against it. ADR-055 D4 separates two gates by
construction -- a working-tree gate inside the dev container over the
uncommitted tree, and this commit gate over a pushed revision -- and no
item may require one artifact to serve both. The lane never was the
working-tree gate's replacement; its steps are the go-native commands
item-0096 documents as that gate, which is why item-0096 now precedes this
item in _order.md rather than depending on it. The "substrate" claim about
item-0016 is withdrawn for the same reason: a lintcue rule runs in the
working-tree gate and the lane runs it too, so item-0016 needs no CI to
exist first and lands just ahead of this item so the first green lane run
covers Beta DoD row 9.

What the lane can execute. A step container reaches no engine: no host
path enters the DAG (ADR-011), no host scratch (ADR-035), host paths bind
only at the operator's engine invocation (ADR-055 D5), and the hardened
profile (ADR-005) is non-configurable, while ADR-055 reserves the nested
topology for the bootstrap proof. internal/testutil/engine.go makes an
unreachable engine a hard failure unless STRIKE_INTEGRATION=0. The commit
gate therefore runs the hermetic suite; the integration suite and the
sigstore harness stay with the working-tree gate. Ratified 2026-09-05 as
the starting point; a later lift is possible and is not this item's.

The ratchet. Ratified 2026-09-05: the ratchet lives in the commit gate,
because it is policy over main, not correctness of a change (D4). The floor
is a one-line file in the tree; the gate rejects a revision below it;
raising it is a commit. The comparator is a small go tool under tools/ --
in-tree gate code, named as a cost, since no form without code was found.
The 61.9 percent recorded at 3db7843 is history: it was measured by make
test with the integration suite included and is not the metric this gate
measures. The initial floor is measured at the landing anchor on the
hermetic suite.

Executor image. Ratified 2026-09-05: the runner consumes strike as a
released, digest-pinned image run as a sibling on its engine -- never a
binary built from the tree it gates, which would be circular, and never
the nested stage_1 image, which D5 reserves for the bootstrap proof.
Hence the hard dependency on item-0062, and through it on item-0150.

Operator-provided, not owned by items (ratified 2026-09-05): the forge
runner; the registry account the deploy targets; branch protection; the
OIDC trust configuration on the forge; the public sigstore keyless chain
rather than the local harness -- whether it offers a Rekor v2 log is
verified at authoring, not assumed here; the DoT resolver and its CA
bundle. Every trust anchor the lane declares is measured at authoring.

Open, to be measured and ratified before authoring: the OIDC flow on the
reference endpoint. ADR-055 D1 lists four capabilities and a browser is
not among them; how a token is minted for a run started from the dev
container is measured there, not designed here.
