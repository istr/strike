Raised by the item-0164 analysis of 2026-10-25. Item-0164 removes the registry deploy validator's check that the pushed image is a pack step: the lane schema admits the image output on a pack step only, so every parsed lane satisfies it. Operator decision of that date: a lane built in Go that bypasses Parse and would not pass it is not an acceptable test input either, except in a test of the validation logic itself. Item-0164 writes that rule into AGENTS.md (Testing) and docs/DEVELOPMENT.md section 2.7; this item owns the existing violations, and item-0164 converts the literals it touches only in the style of the file they sit in.

Classified at dbfdf04, before item-0164, by the test function each literal sits in. Of 74 unpinned image references in test literals, 17 are in validation tests (TestValidatePaths; TestIndexSteps_DuplicateStepID, TestBuild_Cycle and the two leaf-rule tests; the two digest guards TestExecute_DigestGuard and TestResolveImageDigest_RejectsUnpinned), and 57 are in 29 test functions in six files that test DAG order, tree rendering, peer collection, spec hash, cache, input delivery and image resolution. TestValidateDeployArtifactRefs, a validation test, builds steps of no kind. Beyond the unpinned references, nearly every Go-built lane outside the validation tests lacks the required resolver, oidc and keyless blocks, many steps lack args, env, inputs or secrets, and three runtime helpers build steps of no kind (runtimeForSteps in cmd/strike/mock_test.go, newRuntime in internal/deploy/testhelper_test.go, buildDAG in internal/lane/runtime_test.go); the executor.Run tests, the deploy tests and the registry spec-hash tests are affected too, roughly fifteen test files.

No grep decides the property, so the mechanism is the first decision. Item-0154 gates lane snippets in documentation against the same schema and may share the mechanism.
