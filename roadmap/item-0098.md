Restated after the item-0049 landing run. The original item carried two halves;
only the typing half survives, and the optionality half was mis-diagnosed rather
than merely overtaken.

The optionality half is withdrawn. It read: make the resolver block optional so
"a deploy with no DoT resolver (e.g. a registry deploy) serializes an all-empty
resolver object". No such deploy exists and none ever did. #Lane.resolver is a
required field, validateResolver rejects a lane whose resolver is missing its
identity, and cmd/strike initDialer probes the resolver unconditionally at run
start and propagates the error, so a sealed run always carries a verified
observation -- which is what resolverRecord's own doc comment states. The
all-empty record came from test fixtures that built a Sealed value without a
resolver, and the old bare-string fields let them. Constraining one field
(dialedIP) surfaced exactly those fixtures and they were corrected in place.
There is no production state to model as absence.

The typing half is live and narrower than before. #ObservedSSH.hostKeyFingerprint
and #ObservedTLS.serverCertFingerprint are both primitive.#Digest;
#ResolverRecord.serverCertFingerprint is the only fingerprint in the attestation
still declared as a bare string. The item-0049 run typed dialedIP in that same
record and left the fingerprint alone, which is the sibling this item now closes.

Typing host got easier. When this item was written, host was ip:port and an IPv6
literal collided with the #Authority grammar, which is what parked item-0101.
After item-0049, host is adn:port and can never hold an address literal, so
#Authority accepts it as it stands. item-0101 remains open on its own terms for
the ADR-051 registry push target; it no longer blocks this field.

Not folded into item-0049: it is a CUE schema change needing operator
ratification, and that run was already large. The wire is not the reason.
Neither retype changes a serialized byte -- primitive.Digest is a string type,
and the authority projection renders the same packed host:port the field
already carries -- so this item needs no harness and no regeneration. That
inverts the gate: the goldens staying byte-identical is the check, and a golden
diff means the round trip is wrong.

The projection is a pair, and only one half has a precedent. Marshalling
follows #TLS and #SSH, which render Address back to the packed authority.
Decoding has no counterpart on the endpoint types, because a peer is parsed at
the lane boundary through ParseAuthority instead; Sealed's own decoder
dispatches the peers map and the engine union and lets every other field fall
through to the default decoder. A record whose Go host is Address and whose
wire host is a string therefore cannot round-trip unless it carries both halves
itself. It is embedded twice, in the sealed attestation and in the SLSA
external parameters, which is the second reason the pair belongs on the record
rather than on each container.
