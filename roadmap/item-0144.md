Item-0130 landed the keyless clients on the resolved-and-verified dial. In
doing so it created the second beneficiary that the "inline before extracting"
rule (AGENTS.md) requires: `newRegistryTransport` and `HTTPClientFor` now build
structurally the same object -- a host guard, a dialer guard, a 443 port
default, a computed expected authority, a `DialTLSContext` that rejects any
other authority and otherwise dials through `Dialer.DialPeer`, and a
`DialContext` that rejects plaintext. Before item-0130 there was one; the bar
was not met and the duplication did not exist.

The two differ in exactly one respect: the push records the observed connection
identity and the keyless path deliberately does not. That asymmetry is a
decision, not an accident -- ADR-030 records an identity only where it
participates in the trust chain, and ADR-051 D10 puts the push destination
inside a sealed claim while the keyless endpoints are anchored offline in their
own content. A shared construction must keep that decision visible where a
reader meets it. A boolean or an optional-capture parameter would bury it, so
the shape of the seam is the substance of this item, not a detail of it.

Sequencing. `pushIdentityCapture` is rewritten by item-0137, which replaces its
mutex with a compare-and-swap publication (ADR-052 D5). Extracting the shared
construction before that lands would decide the capture's shape twice and
re-edit the same lines; hence the hard dependency rather than a preference in
the execution order.

Open question for ratification: whether the shared construction lives in
`internal/deploy` (both consumers are there today) or is pushed down. ADR-044's
concept-tier amendment scopes `internal/transport` to network carriage -- the
code that dials, verifies and captures identity -- and an `http.RoundTripper`
is protocol assembly above that, which is the reasoning that kept the client
factory in `internal/deploy` during item-0130. That reasoning should be
re-checked against the extracted shape rather than assumed to carry over.

Not in scope: any change to what is recorded. This is a deduplication.
