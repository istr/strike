Owner assigned by the roadmap revision behind ADR-055 (Beta DoD
amendment 4 of 2026-09-05).

At c01be87 the root lane.yaml references a step src it does not declare,
carries a top-level registry key #Lane does not declare, and has no
deploy step; bootstrap/lace.yaml, which ADR-009 names for stage_3, does
not exist; the compare step has had no runnable artifact since ADR-039
D5 made every DAG leaf a deploy step. ADR-055 M5 repaired the
Containerfile, not the lane.

Two design forks to ratify before authoring. First, where the lane lives:
the stage_1 image's CMD ["run"] executes whatever lane file sits at the
repository root, so a commit-gate lane at that path would silently
replace the reproducibility proof; either the bootstrap lane keeps the
root and the gate lane lives elsewhere, or the image's command names its
lane explicitly. Second, what the proof deploys to: every leaf is a
registry deploy under a keyless chain, so the proof needs a registry and
a chain -- the public sigstore chain, or the local harness for a
workstation run -- and the choice determines which trust anchors the lane
declares.

Class and depth follow from the chain, not the file count: nested
engine, three stages, a byte compare, and a publish.
