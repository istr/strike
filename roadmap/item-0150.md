Owner assigned by the roadmap revision behind ADR-055 (Beta DoD
amendment 4 of 2026-09-05).

At c01be87 the root lane.yaml references a step src it does not declare,
carries a top-level registry key #Lane does not declare, and has no
deploy step; bootstrap/lace.yaml, which ADR-009 names for stage_3, does
not exist; the compare step has had no runnable artifact since ADR-039
D5 made every DAG leaf a deploy step. ADR-055 M5 repaired the
Containerfile, not the lane.

Two design forks to ratify before authoring. First, where the lane lives:
the stage_1 image's CMD ["run"] executes whatever lane file sits at the
repository root, so a commit-gate lane at that path would silently
replace the reproducibility proof; either the bootstrap lane keeps the
root and the gate lane lives elsewhere, or the image's command names its
lane explicitly. Second, what the proof deploys to: every leaf is a
registry deploy under a keyless chain, so the proof needs a registry and
a chain -- the public sigstore chain, or the local harness for a
workstation run -- and the choice determines which trust anchors the lane
declares.

Class and depth follow from the chain, not the file count: nested
engine, three stages, a byte compare, and a publish.

## Amendment 2026-09-14 at 7b09365: the item is narrowed to lane authoring under the sibling topology

Review against the two bootstrap reports of 2026-09-14 found that the
stage_3-inside-stage_2 mechanism this item inherited from ADR-009 cannot
run: the packed stage_2 image carries no engine, and a step container can
neither reach the stage_1 engine nor start its own under ADR-005 and
ADR-055 D5. It also found that the compare is not expressible in the lane
schema, because an image output cannot be mounted as a file input
(ADR-046). The single nesting of stage_1 itself was then weighed and
retired: nesting enlarges the trusted computing base by an unattested
engine image without taking the host engine out of it. Four blockers are
split out and this item depends on them: item-0155 ratifies the sibling
topology and the no-nesting principle by ADR amendment, item-0156 measures
the sibling run line on the reference endpoint, item-0157 lands the source
fetch step, item-0158 lands the compare step kind. What stays here is
authoring the lane against the decided shape.

The two design forks recorded above are resolved as proposals, not
decisions: fork one, the image command names its lane file explicitly,
because a commit-gate lane at the repository root would otherwise
silently replace the proof; fork two, the proof is chain-independent, so
the workstation run deploys under the local harness and the publish runs
under the public chain wherever an id token exists, with the split into
one or two lane files left to authoring. One follow-up sits beside this
item rather than inside it: item-0160 (reproduction outside the bootstrap).
